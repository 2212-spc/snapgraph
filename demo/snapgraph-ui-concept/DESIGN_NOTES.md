# SnapGraph UI Concept Demo 设计说明

这个文件夹是比赛叙事用的独立前端概念原型，不替代生产 Vue 前端。它的目标不是把所有功能塞满，而是先回答一个问题：评委第一次看到 SnapGraph 时，能不能立刻理解“我们不是又一个 AI 知识库，我们在保存人的判断来路”。

## 总体设计理念

SnapGraph 的界面应该像一个安静但可靠的认知工作台：资料可以很多，但屏幕第一优先级永远是“用户当时为什么在乎”。所以默认首页不是图谱、不是文件列表、不是 AI 聊天，而是“找回过去的判断”。

视觉语言选择“深色书脊 + 纸面工作台 + 证据标签”。深色左侧栏承担产品身份和层级，纸面区域承载具体材料，绿色/琥珀/红色分别标出用户原话、AI 推断和低置信审计。这套颜色不是装饰，而是产品伦理：AI 可以参与，但不能冒充用户。

## 页面结构决策

| 区域 | 是否需要 | 放在哪里 | 呈现形式 | 设计理由 |
|---|---|---|---|---|
| 左侧导航 | 需要 | 全局左侧，移动端置顶 | 深色 rail + 四个层级入口 | 让产品像工作台而不是营销页；四个入口对应核心流程：找回、收集、图谱、审计。 |
| 顶部状态条 | 需要 | 主内容顶部右侧 | user-stated / AI-inferred / needs review 三个状态标签 | 把可信边界放到第一屏，证明“AI 不假装是你”不是一句口号。 |
| 找回页 | 必须 | 默认首屏 | 一个问题输入区 + 找回原话 + 证据路径 | 产品价值最高的瞬间是“过去的我回答现在的我”，所以它必须是第一屏。 |
| 思考回执 | 必须 | 右侧信任栏和收集页预览 | 类似纸质回执的结构化卡片 | 它是 SnapGraph 的核心交互隐喻：每次保存资料，都留下一个可追溯的判断。 |
| 信任边界 | 必须 | 找回页右侧 | U / AI / ? 三个状态说明 | 评委需要看到我们如何处理幻觉、推断和用户原话；放右侧是因为它像证据侧栏。 |
| 收集页 | 必须 | 第二入口 | 资料投放区 + “为什么重要”输入 + 回执预览 | 保存动作不能只收文件，必须强迫产品询问“为什么值得留下”。 |
| 图谱页 | 需要但降权 | 第三入口 | 记忆空间列表 + 证据路径图 | 图谱有吸引力，但不能抢走故事主角；它用于解释连接和路径，不做炫技 3D。 |
| 审计页 | 必须 | 第四入口 | 低置信推断列表 + 改写/确认操作 | 把“不确定”做成产品状态，体现 AIGC 作品的成熟度和责任感。 |

## 四个视图的叙事职责

1. 找回：证明 SnapGraph 的情感价值。用户问“我之前为什么觉得这个方向重要？”，系统先还给他自己的原话。
2. 收集：证明 SnapGraph 的交互创新。保存资料时生成“思考回执”，保存 what 的同时保存 why。
3. 图谱：证明 SnapGraph 的长期价值。资料、判断、项目和 open loop 可以连成路径，但路径服务于理解，不是为了展示复杂。
4. 审计：证明 SnapGraph 的可信 AI 立场。低置信推断不会被包装成确定结论，而是等待用户确认。

## 关键取舍

- 不做传统 dashboard 首页，因为它会把 SnapGraph 讲成效率工具。
- 不把聊天框做成唯一主角，因为普通 AI 助手会替用户回答，而 SnapGraph 要召回用户自己的回答。
- 不做 3D 大图谱，因为比赛第一版最重要的是概念清楚、交互可信、价值打动人。
- 保留少量可点击反馈：导航切换、快捷问题、回执预览更新。它足够说明流程，但不会把 demo 变成重工程。

## 后续迁移建议

确认方向后，可以把这个 demo 的视觉和信息架构迁回 `frontend/src`：优先改 `RecallHome.vue`、`CollectView.vue`、`SpacesView.vue` 和全局 `styles.css`。生产版再接入真实 API、诊断状态和 MockLLM/真实 LLM 的切换。
